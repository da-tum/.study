📐 Unit 1: Introduction to Algorithms, Complexity & Recursion

A comprehensive review of Big-O notations, recursion call stacks, algorithm design paradigms, and search mechanics.

1. Linear vs. Non-Linear Structures

Linear structures (Arrays, Stacks, Queues, Linked Lists) organize nodes sequentially in a 1D sequence. Non-linear structures (Trees, Graphs) arrange nodes hierarchically or in complex networks.

2. Asymptotic Notations

  • Big-O ($O$): Represents the upper bound or worst-case complexity: $f(n) \le c \cdot g(n)$ for all $n \ge n_0$.
  • Omega ($\Omega$): Represents the lower bound or best-case complexity: $f(n) \ge c \cdot g(n)$ for all $n \ge n_0$.
  • Theta ($\Theta$): Represents the tight exact bound: $c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$ for all $n \ge n_0$.

3. Algorithm Design Paradigms

Paradigm Key Strategy Global Optimality Classic Example
Divide & Conquer Divides problems recursively, solves subproblems, merges solutions. Guaranteed (exact solutions). Merge Sort, Quick Sort, Binary Search
Greedy Algorithms Makes local optimal choice at each step hoping to find global optimum. Not guaranteed (can yield sub-optimal results). Prim's & Kruskal's MST, Fractional Knapsack
Dynamic Programming Stores solved overlapping subproblem results to prevent re-computation. Guaranteed (global optimization). 0/1 Knapsack, Fibonacci Series, Floyd-Warshall

4. Recursion vs. Iteration Call Stack Memory

Iteration runs in $O(1)$ auxiliary space because it repeats instructions inside a single frame scope. Recursion uses a LIFO call stack to store temporary activation frames for every self-call, leading to $O(n)$ space complexity.

# Iterative Factorial (O(1) auxiliary space)
def fact_iter(n):
    res = 1
    for i in range(1, n + 1):
        res *= i
    return res

# Recursive Factorial (O(n) auxiliary call stack space)
def fact_recur(n):
    if n <= 1:
        return 1
    return n * fact_recur(n - 1)

class Node:

class LinkedList:
    def __init__(self):
        self.head = None

    # Insert at Beginning: O(1)
    def insert_beginning(self, data):
        new_node = Node(data)
        new_node.next = self.head
        self.head = new_node

    # Insert at End: O(n) without tail pointer, O(1) with tail
    def insert_end(self, data):
        new_node = Node(data)
        if not self.head:
            self.head = new_node
            return
        temp = self.head
        while temp.next:
            temp = temp.next
        temp.next = new_node

4. Stacks & Circular Queues

Overflow: Attempting to insert into a full structure. Underflow: Attempting to remove from an empty structure.

# Circular Queue array-based implementation
class CircularQueue:
    def __init__(self, size):
        self.size = size
        self.queue = [None] * size
        self.front = -1
        self.rear = -1

    def enqueue(self, item):
        if (self.rear + 1) % self.size == self.front:
            print("Overflow Error!")
            return
        if self.front == -1:
            self.front = 0
            self.rear = 0
        else:
            self.rear = (self.rear + 1) % self.size
        self.queue[self.rear] = item

    def dequeue(self):
        if self.front == -1:
            print("Underflow Error!")
            return None
        item = self.queue[self.front]
        if self.front == self.rear:
            self.front = -1
            self.rear = -1
        else:
            self.front = (self.front + 1) % self.size
        return item

🗄️ Unit 3: Sorting & Searching Algorithms

Covers stable/unstable sorts, in-place/out-of-place constraints, operational steps of $O(n^2)$ sorts, and full recursive $O(n \log n)$ implementations.

1. Core Taxonomies

  • Stable Sorting: Preserves the relative order of duplicate elements. Examples: Merge Sort, Insertion Sort, Bubble Sort.
  • Unstable Sorting: May alter the relative order of duplicate elements. Examples: Quick Sort, Selection Sort, Heap Sort.
  • In-Place: Operates directly on the input array requiring constant $O(1)$ auxiliary space. Examples: Quick Sort (excluding recursive stack), Insertion Sort, Bubble Sort.
  • Out-of-Place: Requires additional auxiliary array allocations to sort. Example: Merge Sort ($O(n)$ space).

2. $O(n \log n)$ Sorts in Python

# Merge Sort (Guaranteed O(n log n) time, O(n) space)
def merge_sort(arr):
    if len(arr) > 1:
        mid = len(arr) // 2
        L = arr[:mid]
        R = arr[mid:]
        merge_sort(L)
        merge_sort(R)
        i = j = k = 0
        while i < len(L) and j < len(R):
            if L[i] < R[j]:
                arr[k] = L[i]; i += 1
            else:
                arr[k] = R[j]; j += 1
            k += 1
        while i < len(L):
            arr[k] = L[i]; i += 1; k += 1
        while j < len(R):
            arr[k] = R[j]; j += 1; k += 1

# Quick Sort (O(n log n) average time, O(n^2) worst case, O(log n) stack space)
def quick_sort(arr, low, high):
    if low < high:
        p = partition(arr, low, high)
        quick_sort(arr, low, p - 1)
        quick_sort(arr, p + 1, high)

def partition(arr, low, high):
    pivot = arr[low] # first element pivot
    i = low + 1
    j = high
    while True:
        while i <= j and arr[i] <= pivot:
            i += 1
        while i <= j and arr[j] >= pivot:
            j -= 1
        if i <= j:
            arr[i], arr[j] = arr[j], arr[i]
        else:
            break
    arr[low], arr[j] = arr[j], arr[low]
    return j

1. Trees and Reconstruction Rules

  • Reconstruction Rules: A unique binary tree can be reconstructed from **Preorder + Inorder** or **Postorder + Inorder**. Why Preorder + Postorder is impossible: Lacks relative direction. Without inorder data to partition left/right subtrees, we cannot distinguish between a parent node having only a left child vs. only a right child, resulting in structural ambiguity.

2. Binary Search Tree (BST) Operations

class TreeNode:
    def __init__(self, key):
        self.val = key
        self.left = None
        self.right = None

# BST Insertion: O(log n) average, O(n) skewed worst case
def insert_bst(root, key):
    if not root:
        return TreeNode(key)
    if key < root.val:
        root.left = insert_bst(root.left, key)
    else:
        root.right = insert_bst(root.right, key)
    return root

3. Graph Traversal Algorithms (BFS vs. DFS)

# Graph BFS (Queue-based Level-by-level traversal)
def bfs(graph, start):
    visited = set([start])
    queue = [start]
    res = []
    while queue:
        node = queue.pop(0)
        res.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return res

# Graph DFS (Recursive/Stack-based Branch-by-branch traversal)
def dfs(graph, node, visited=None, res=None):
    if visited is None: visited = set()
    if res is None: res = []
    visited.add(node)
    res.append(node)
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited, res)
    return res

4. Hashing Collision Resolutions

  • Separate Chaining: Array slots hold pointers to linked list heads. Colliding elements are appended to the linked list. Advantages: Table never fills, simple deletion. Disadvantage: Extra pointer memory overhead.
  • Linear Probing (Open Addressing): Colliding elements are placed in the next available contiguous slot: h(x, i) = (h(x) + i) % m. Advantages: No pointer overhead, good cache performance. Disadvantage: Primary clustering (runs of occupied slots slow down lookups).

❓ Q2: Find Time Complexity: i = 1; while i <= n: i = i * 3.

Correct Answer:

In each step, $i$ is multiplied by 3. Its value grows exponentially: $1, 3, 9, 27, \dots, 3^k$. The loop terminates when $3^k \ge n$. Taking the logarithm to base 3 on both sides:

$$k = \log_3 n$$

Thus, the exact Time Complexity is **$O(\log n)$** (Logarithmic).

❓ Q3: AVL balance factor and rotations rules.

Correct Answer:

The Balance Factor ($BF$) of a node is calculated as: BF = Height(Left Subtree) - Height(Right Subtree).

For an AVL tree to remain balanced, the balance factor of every node must be $-1$, $0$, or $+1$. If $|BF| > 1$, four types of rotations restore balance:

  • Left-Left (LL) Case: Single Right Rotation around the parent.
  • Right-Right (RR) Case: Single Left Rotation around the parent.
  • Left-Right (LR) Case: Single Left Rotation on the left child, followed by a Single Right Rotation on the parent.
  • Right-Left (RL) Case: Single Right Rotation on the right child, followed by a Single Left Rotation on the parent.

❓ Q4: Stack Rearrangement (Even on Top, Odd on Bottom).

Correct Answer:

To rearrange elements in a stack (initial `[1, 2, 3, 4, 5, 6, 7, 8]` with `1` at the top and `8` at the bottom) so that evens go on top and odds go to the bottom using an auxiliary stack:

def rearrange_stack(stack):
    evens = []
    odds = []
    
    # 1. Pop all elements from stack and partition
    while stack:
        val = stack.pop()
        if val % 2 == 0:
            evens.append(val)
        else:
            odds.append(val)
            
    # 2. Push odds first (they go to the bottom)
    for o in sorted(odds): # maintain original or sorted order
        stack.append(o)
        
    # 3. Push evens next (they sit on top of odds)
    for e in sorted(evens):
        stack.append(e)
    return stack

❓ Q5: Circular Queue Overcoming Linear Queue limitations.

Correct Answer:

In a **Linear Queue**, once the `rear` reaches `MAX_SIZE - 1`, the queue is declared full, even if several dequeue operations have occurred and slots at the front are empty. This is a waste of memory.

A **Circular Queue** overcomes this by wrapping pointers circularly using modulo arithmetic: `rear = (rear + 1) % MAX_SIZE`. This allows empty front slots to be recycled.

  • Enqueue: rear = (rear + 1) % MAX_SIZE
  • Dequeue: front = (front + 1) % MAX_SIZE
  • Full Condition: (rear + 1) % MAX_SIZE == front

❓ Q6: Why is binary search mathematically impossible to reconstruct using only Preorder and Postorder traversals?

Correct Answer:

Preorder traversal visits **[Root, Left, Right]** and Postorder visits **[Left, Right, Root]**. Both list the root but do not tell where the boundary between the left and right subtrees lies. Without **Inorder** traversal (which visits **[Left, Root, Right]**) to act as a separator, we cannot know if a node is a left child or a right child when a parent has only one child. This leads to multiple structurally different trees matching the same Preorder and Postorder traversals, causing ambiguity.
