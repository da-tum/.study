📐 Unit 1: Introduction to Algorithms, Complexity & Recursion

A comprehensive review of Big-O notations, recursion call stacks, algorithm design paradigms, and search mechanics.

1. Linear vs. Non-Linear Structures

Linear structures (Arrays, Stacks, Queues, Linked Lists) organize nodes sequentially in a 1D sequence. Non-linear structures (Trees, Graphs) arrange nodes hierarchically or in complex networks.

2. Asymptotic Notations

  • Big-O ($O$): Represents the upper bound or worst-case complexity: $f(n) \le c \cdot g(n)$ for all $n \ge n_0$.
  • Omega ($\Omega$): Represents the lower bound or best-case complexity: $f(n) \ge c \cdot g(n)$ for all $n \ge n_0$.
  • Theta ($\Theta$): Represents the tight exact bound: $c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$ for all $n \ge n_0$.

3. Algorithm Design Paradigms

Paradigm Key Strategy Global Optimality Classic Example
Divide & Conquer Divides problems recursively, solves subproblems, merges solutions. Guaranteed (exact solutions). Merge Sort, Quick Sort, Binary Search
Greedy Algorithms Makes local optimal choice at each step hoping to find global optimum. Not guaranteed (can yield sub-optimal results). Prim's & Kruskal's MST, Fractional Knapsack
Dynamic Programming Stores solved overlapping subproblem results to prevent re-computation. Guaranteed (global optimization). 0/1 Knapsack, Fibonacci Series, Floyd-Warshall

4. Recursion vs. Iteration Call Stack Memory

Iteration runs in $O(1)$ auxiliary space because it repeats instructions inside a single frame scope. Recursion uses a LIFO call stack to store temporary activation frames for every self-call, leading to $O(n)$ space complexity.

# Iterative Factorial (O(1) auxiliary space)
def fact_iter(n):
    res = 1
    for i in range(1, n + 1):
        res *= i
    return res

# Recursive Factorial (O(n) auxiliary call stack space)
def fact_recur(n):
    if n <= 1:
        return 1
    return n * fact_recur(n - 1)

class Node:

class LinkedList:
    def __init__(self):
        self.head = None

    # Insert at Beginning: O(1)
    def insert_beginning(self, data):
        new_node = Node(data)
        new_node.next = self.head
        self.head = new_node

    # Insert at End: O(n) without tail pointer, O(1) with tail
    def insert_end(self, data):
        new_node = Node(data)
        if not self.head:
            self.head = new_node
            return
        temp = self.head
        while temp.next:
            temp = temp.next
        temp.next = new_node

4. Stacks & Circular Queues

Overflow: Attempting to insert into a full structure. Underflow: Attempting to remove from an empty structure.

# Circular Queue array-based implementation
class CircularQueue:
    def __init__(self, size):
        self.size = size
        self.queue = [None] * size
        self.front = -1
        self.rear = -1

    def enqueue(self, item):
        if (self.rear + 1) % self.size == self.front:
            print("Overflow Error!")
            return
        if self.front == -1:
            self.front = 0
            self.rear = 0
        else:
            self.rear = (self.rear + 1) % self.size
        self.queue[self.rear] = item

    def dequeue(self):
        if self.front == -1:
            print("Underflow Error!")
            return None
        item = self.queue[self.front]
        if self.front == self.rear:
            self.front = -1
            self.rear = -1
        else:
            self.front = (self.front + 1) % self.size
        return item

🗄️ Unit 3: Sorting & Searching Algorithms

Covers stable/unstable sorts, in-place/out-of-place constraints, operational steps of $O(n^2)$ sorts, and full recursive $O(n \log n)$ implementations.

1. Core Taxonomies

  • Stable Sorting: Preserves the relative order of duplicate elements. Examples: Merge Sort, Insertion Sort, Bubble Sort.
  • Unstable Sorting: May alter the relative order of duplicate elements. Examples: Quick Sort, Selection Sort, Heap Sort.
  • In-Place: Operates directly on the input array requiring constant $O(1)$ auxiliary space. Examples: Quick Sort (excluding recursive stack), Insertion Sort, Bubble Sort.
  • Out-of-Place: Requires additional auxiliary array allocations to sort. Example: Merge Sort ($O(n)$ space).

2. $O(n \log n)$ Sorts in Python

# Merge Sort (Guaranteed O(n log n) time, O(n) space)
def merge_sort(arr):
    if len(arr) > 1:
        mid = len(arr) // 2
        L = arr[:mid]
        R = arr[mid:]
        merge_sort(L)
        merge_sort(R)
        i = j = k = 0
        while i < len(L) and j < len(R):
            if L[i] < R[j]:
                arr[k] = L[i]; i += 1
            else:
                arr[k] = R[j]; j += 1
            k += 1
        while i < len(L):
            arr[k] = L[i]; i += 1; k += 1
        while j < len(R):
            arr[k] = R[j]; j += 1; k += 1

# Quick Sort (O(n log n) average time, O(n^2) worst case, O(log n) stack space)
def quick_sort(arr, low, high):
    if low < high:
        p = partition(arr, low, high)
        quick_sort(arr, low, p - 1)
        quick_sort(arr, p + 1, high)

def partition(arr, low, high):
    pivot = arr[low] # first element pivot
    i = low + 1
    j = high
    while True:
        while i <= j and arr[i] <= pivot:
            i += 1
        while i <= j and arr[j] >= pivot:
            j -= 1
        if i <= j:
            arr[i], arr[j] = arr[j], arr[i]
        else:
            break
    arr[low], arr[j] = arr[j], arr[low]
    return j

1. Trees and Reconstruction Rules

  • Reconstruction Rules: A unique binary tree can be reconstructed from **Preorder + Inorder** or **Postorder + Inorder**. Why Preorder + Postorder is impossible: Lacks relative direction. Without inorder data to partition left/right subtrees, we cannot distinguish between a parent node having only a left child vs. only a right child, resulting in structural ambiguity.

2. Binary Search Tree (BST) Operations

class TreeNode:
    def __init__(self, key):
        self.val = key
        self.left = None
        self.right = None

# BST Insertion: O(log n) average, O(n) skewed worst case
def insert_bst(root, key):
    if not root:
        return TreeNode(key)
    if key < root.val:
        root.left = insert_bst(root.left, key)
    else:
        root.right = insert_bst(root.right, key)
    return root

3. Graph Traversal Algorithms (BFS vs. DFS)

# Graph BFS (Queue-based Level-by-level traversal)
def bfs(graph, start):
    visited = set([start])
    queue = [start]
    res = []
    while queue:
        node = queue.pop(0)
        res.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return res

# Graph DFS (Recursive/Stack-based Branch-by-branch traversal)
def dfs(graph, node, visited=None, res=None):
    if visited is None: visited = set()
    if res is None: res = []
    visited.add(node)
    res.append(node)
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited, res)
    return res

4. Hashing Collision Resolutions

  • Separate Chaining: Array slots hold pointers to linked list heads. Colliding elements are appended to the linked list. Advantages: Table never fills, simple deletion. Disadvantage: Extra pointer memory overhead.
  • Linear Probing (Open Addressing): Colliding elements are placed in the next available contiguous slot: h(x, i) = (h(x) + i) % m. Advantages: No pointer overhead, good cache performance. Disadvantage: Primary clustering (runs of occupied slots slow down lookups).

❓ Q2: Find Time Complexity: i = 1; while i <= n: i = i * 3.

Correct Answer:

In each step, $i$ is multiplied by 3. Its value grows exponentially: $1, 3, 9, 27, \dots, 3^k$. The loop terminates when $3^k \ge n$. Taking the logarithm to base 3 on both sides:

$$k = \log_3 n$$

Thus, the exact Time Complexity is **$O(\log n)$** (Logarithmic).

❓ Q3: AVL balance factor and rotations rules.

Correct Answer:

The Balance Factor ($BF$) of a node is calculated as: BF = Height(Left Subtree) - Height(Right Subtree).

For an AVL tree to remain balanced, the balance factor of every node must be $-1$, $0$, or $+1$. If $|BF| > 1$, four types of rotations restore balance:

  • Left-Left (LL) Case: Single Right Rotation around the parent.
  • Right-Right (RR) Case: Single Left Rotation around the parent.
  • Left-Right (LR) Case: Single Left Rotation on the left child, followed by a Single Right Rotation on the parent.
  • Right-Left (RL) Case: Single Right Rotation on the right child, followed by a Single Left Rotation on the parent.

❓ Q4: Stack Rearrangement (Even on Top, Odd on Bottom).

Correct Answer:

To rearrange elements in a stack (initial `[1, 2, 3, 4, 5, 6, 7, 8]` with `1` at the top and `8` at the bottom) so that evens go on top and odds go to the bottom using an auxiliary stack:

def rearrange_stack(stack):
    evens = []
    odds = []
    
    # 1. Pop all elements from stack and partition
    while stack:
        val = stack.pop()
        if val % 2 == 0:
            evens.append(val)
        else:
            odds.append(val)
            
    # 2. Push odds first (they go to the bottom)
    for o in sorted(odds): # maintain original or sorted order
        stack.append(o)
        
    # 3. Push evens next (they sit on top of odds)
    for e in sorted(evens):
        stack.append(e)
    return stack

❓ Q5: Circular Queue Overcoming Linear Queue limitations.

Correct Answer:

In a **Linear Queue**, once the `rear` reaches `MAX_SIZE - 1`, the queue is declared full, even if several dequeue operations have occurred and slots at the front are empty. This is a waste of memory.

A **Circular Queue** overcomes this by wrapping pointers circularly using modulo arithmetic: `rear = (rear + 1) % MAX_SIZE`. This allows empty front slots to be recycled.

  • Enqueue: rear = (rear + 1) % MAX_SIZE
  • Dequeue: front = (front + 1) % MAX_SIZE
  • Full Condition: (rear + 1) % MAX_SIZE == front

❓ Q6: Why is binary search mathematically impossible to reconstruct using only Preorder and Postorder traversals?

Correct Answer:

Preorder traversal visits **[Root, Left, Right]** and Postorder visits **[Left, Right, Root]**. Both list the root but do not tell where the boundary between the left and right subtrees lies. Without **Inorder** traversal (which visits **[Left, Root, Right]**) to act as a separator, we cannot know if a node is a left child or a right child when a parent has only one child. This leads to multiple structurally different trees matching the same Preorder and Postorder traversals, causing ambiguity.

    1. Partitioning Theory & Pivot Selection

    We use Hoare's Partitioning Algorithm. The first element of the array (or active subarray) is selected as the pivot. Two pointers, $i$ and $j$, are initialized at the left boundary + 1 and the right boundary, respectively.

    • Pointer $i$ scans from left-to-right looking for the first element strictly greater than the pivot.
    • Pointer $j$ scans from right-to-left looking for the first element strictly smaller than or equal to the pivot.
    • If pointers have not crossed ($i < j$), we swap their values and resume scanning.
    • If pointers cross ($i \ge j$), scanning terminates. We swap the pivot with arr[j]. Node arr[j] is now in its final sorted position.

    def quick_sort(arr, low, high):
    if low < high:
        # Partition the array and retrieve pivot index
        p_index = partition(arr, low, high)
        
        # Recursively sort elements before and after partition
        quick_sort(arr, low, p_index - 1)
        quick_sort(arr, p_index + 1, high)

def partition(arr, low, high):
    pivot = arr[low]  # Choose first element as pivot
    i = low + 1
    j = high
    
    while True:
        # Increment i while elements are smaller or equal to pivot
        while i <= j and arr[i] <= pivot:
            i += 1
        # Decrement j while elements are greater than pivot
        while i <= j and arr[j] > pivot:
            j -= 1
        
        if i < j:
            # Swap out-of-order elements
            arr[i], arr[j] = arr[j], arr[i]
        else:
            # Pointers crossed, partition complete
            break
            
    # Swap pivot with elements at j boundary
    arr[low], arr[j] = arr[j], arr[low]
    return j  # Return pivot index

class ArrayStack:
    def __init__(self, capacity=5):
        self.capacity = capacity
        self.arr = [None] * capacity
        self.top = -1  # Pointer initialized to -1 (empty stack)
        
    def push(self, item):
        if self.top >= self.capacity - 1:
            raise StackOverflowException("Stack Overflow: Cannot push element!")
        self.top += 1
        self.arr[self.top] = item

        if self.is_empty():
            raise StackUnderflowException("Stack Underflow: Cannot pop from empty stack!")
        popped_val = self.arr[self.top]
        self.arr[self.top] = None # Clear memory slot
        self.top -= 1
        return popped_val

        if self.is_empty():
            return None
        return self.arr[self.top]
        
    def is_empty(self):
        return self.top == -1
        
    def get_state(self):
        return [self.arr[idx] for idx in range(self.top + 1)]

    Q7. Complexity Analysis: Analyze loop structures sequential O(n), logarithmic O(log n), quadratic O(n²). 8 Marks

    1. Sequential Linear Loop ($O(n)$)

    # Snippet A
for i in range(n):
    print(i)

    Mathematical Derivation: Let $T(n)$ represent the total operations. The loop executes the single print statement for each value of $i$ in the range $[0, n-1]$. $$T(n) = \sum_{i=0}^{n-1} 1 = n$$ As $n$ grows, execution steps grow linearly. Thus, the time complexity is $O(n)$.

    • Best Case: $O(n)$ (Loop must always iterate $n$ times).
    • Average Case: $O(n)$
    • Worst Case: $O(n)$

    2. Logarithmic Loop ($O(\log n)$)

    # Snippet B
i = 1
while i < n:
    i = i * 3

    Mathematical Derivation: Let $k$ represent the iteration count. The variable $i$ starts at 1 and is multiplied by 3 in each iteration step:

    • Iteration 1: $i = 1 \cdot 3 = 3^1$
    • Iteration 2: $i = 3 \cdot 3 = 9 = 3^2$
    • Iteration $k$: $i = 3^k$
    The loop terminates when $i \ge n \Rightarrow 3^k \ge n$. Taking log to the base 3 on both sides: $$\log_3(3^k) \ge \log_3 n \implies k \ge \log_3 n$$ The total steps grow logarithmically with input size $n$. Thus, the time complexity is $O(\log n)$.
    • Best/Avg/Worst Case: $O(\log n)$

    3. Nested Quadratic Loop ($O(n^2)$)

    # Snippet C
for i in range(n):
    for j in range(n):
        print(i, j)

    Mathematical Derivation: The outer loop runs sequentially $n$ times. For each iteration of the outer loop, the inner loop also runs $n$ times. $$T(n) = \sum_{i=0}^{n-1} \left( \sum_{j=0}^{n-1} 1 ight) = \sum_{i=0}^{n-1} n = n \cdot n = n^2$$ The execution steps grow quadratically. Thus, the time complexity is $O(n^2)$.

    • Best/Avg/Worst Case: $O(n^2)$

    Time Complexity: O(log n), Space Complexity: O(1)

            low = mid + 1  # Eliminate left half

    class Stack:
    def __init__(self, max_size=100):
        self.stack = []
        self.max_size = max_size

    def is_empty(self):
        return len(self.stack) == 0

    def is_full(self):
        return len(self.stack) == self.max_size

    # PUSH — O(1) amortized
    def push(self, item):
        if self.is_full():
            print("Stack Overflow! Cannot push.")
            return
        self.stack.append(item)
        print(f"Pushed: {item}")

    # POP — O(1)
    def pop(self):
        if self.is_empty():
            print("Stack Underflow! Cannot pop.")
            return None
        return self.stack.pop()

    def peek(self):
        if self.is_empty():
            return None
        return self.stack[-1]

    def display(self):
        print("Stack (top to bottom):", self.stack[::-1])

    def insertion_sort(arr):
    n = len(arr)
    for i in range(1, n):
        key = arr[i]
        j = i - 1
        # Shift elements greater than key one position right
        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key  # Place key in correct position
    return arr

    Asymptotic notations mathematically describe how an algorithm's resource usage (time/space) grows relative to input size $n$.

    NotationNameMeaningFormal Definition
    $O(g(n))$Big-OUpper Bound (Worst Case)$f(n) \le c \cdot g(n)$ for all $n \ge n_0$

    def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])    # Conquer left half

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:     # <= ensures stability
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])         # Append remaining
    result.extend(right[j:])
    return result

def partition(arr, low, high):
    pivot = arr[low]
    i = low + 1
    j = high
    while True:
        while i <= j and arr[i] <= pivot: i += 1
        while i <= j and arr[j] >= pivot: j -= 1
        if i <= j:
            arr[i], arr[j] = arr[j], arr[i]
        else:
            break
    arr[low], arr[j] = arr[j], arr[low]  # Place pivot
    return j

    Q5. Find the time complexity of a loop where i is multiplied by 2 or 3 in every iteration. Unit 1

    Let's derive the time complexity mathematically for both multiplication factors:

    Case 1: Multiplied by 2 (i = i * 2)

    i = 1
while i < n:
    i = i * 2
    • Let $k$ be the number of iterations of the loop.
    • In each iteration, the value of $i$ grows exponentially: $i = 1, 2, 4, 8, \dots, 2^k$.
    • The loop terminates when $i \ge n$. At the final step: $2^k \ge n$.
    • Taking base-2 logarithm on both sides: $k \ge \log_2 n$.
    • Thus, the loop runs exactly $\lceil \log_2 n \rceil$ times $\Rightarrow$ Time Complexity = $O(\log n)$.

    Case 2: Multiplied by 3 (i = i * 3)

    i = 1
while i < n:
    i = i * 3
    • Similarly, in the $k$-th iteration, $i = 3^k$.
    • Termination condition: $3^k \ge n \Rightarrow k \ge \log_3 n$.
    • Since $\log_3 n = \frac{\log_2 n}{\log_2 3}$, base change rules state that the base of the logarithm acts as a constant scaling factor. In Big-O, constant factors are dropped.
    • Therefore, Time Complexity = $O(\log n)$.
    Always write the math proof in a step-by-step format as shown above to guarantee full marks in university exams.
    Q6. Find the time complexity of a single loop, nested loop, and half-reduction loop. Unit 1

    Here is a breakdown of the three classic loop paradigms with mathematical derivations:

    1. Single Loop (Linear Growth):

    for i in range(0, n, 2):
    print(i)
    • The loop index increment is additive (step size = 2).
    • The loop executes exactly $n/2$ times.
    • Dropping the constant factor $1/2$: Time Complexity = $O(n)$.

    2. Nested Loop (Quadratic Growth):

    for i in range(n):
    for j in range(n):
        print(i, j)
    • The outer loop runs $n$ times.
    • For every single iteration of the outer loop, the inner loop runs $n$ times.
    • Total executions = $n \times n = n^2 \Rightarrow$ Time Complexity = $O(n^2)$.

    3. Half-Reduction Loop (Logarithmic Growth):

    i = n
while i > 1:
    i = i // 2
    • The loop index is divided by 2 in each iteration.
    • The value sequence is $n, n/2, n/4, \dots, n/2^k$.
    • The loop terminates when $i \le 1 \Rightarrow n/2^k \le 1 \Rightarrow 2^k \ge n \Rightarrow k \ge \log_2 n$.
    • Total iterations = $\log_2 n \Rightarrow$ Time Complexity = $O(\log n)$.
    Q7. Explain best-case, average-case, and worst-case complexity using searching as an example. Unit 1

    Let's explain asymptotic cases using Linear Search on an array of size $n$ as our analytical example:

    • Best-Case Complexity ($\Omega$): Occurs when the algorithm performs the absolute minimum number of operations for a highly favorable input.
      Linear Search Example: The target element is at the very first index of the array (index 0). Only 1 comparison is performed.
      Asymptotic Notation: $\Omega(1)$ (Constant time).
    • Worst-Case Complexity ($O$): Occurs when the input forces the algorithm to execute its maximum possible steps. This is the most crucial benchmark for safety and performance guarantees.
      Linear Search Example: The target element is at the very last index ($n-1$) or is entirely absent from the array, forcing the loop to scan all $n$ items.
      Asymptotic Notation: $O(n)$ (Linear time).
    • Average-Case Complexity ($\Theta$): Represents the expected average execution behavior over all possible inputs.
      Linear Search Example: Assuming the target element is uniformly distributed, it will be found in the middle of the array on average (taking $n/2$ steps).
      Asymptotic Notation: $\Theta(n)$ (Linear time, since constant factors like $1/2$ are ignored).

    Q9. Explain recursion using factorial or Fibonacci. Unit 1
    Recursion is a programming technique where a function calls itself directly or indirectly to solve a smaller instance of the same problem, continuing until it hits a defined Base Case that terminates the execution.

    Let's analyze Recursive Factorial $n! = n \times (n-1)!$:

    def factorial(n):
    if n <= 1:         # Base Case
        return 1
    return n * factorial(n - 1)  # Recursive Step

    Stack Memory Lifecycle for factorial(3):

    1. factorial(3) is called $\rightarrow$ active frame pushed to call stack, waits for factorial(2).
    2. factorial(2) is called $\rightarrow$ active frame pushed, waits for factorial(1).
    3. factorial(1) is called $\rightarrow$ hits Base Case, returns 1.
    4. Stack starts unwinding: factorial(2) receives 1 $\rightarrow$ returns $2 \times 1 = 2$.
    5. factorial(3) receives 2 $\rightarrow$ returns $3 \times 2 = 6$. Final result is 6. Stack is clear.
    Without a base case, recursion leads to infinite self-calls and triggers a Stack Overflow Error.

    Q12. Explain why insertion at the beginning of an array takes O(n) time. Unit 2

    1. Element Shifting: We cannot overwrite index 0 without losing data. We must move the current element at index $n-1$ to $n$, the element at $n-2$ to $n-1$, and so on, until the element at index 0 is shifted to index 1.
    2. This shifting loop must execute exactly $n$ times (where $n$ is the number of active elements in the array).
    3. Once the shifting loop is complete, index 0 is vacant, and the new element is inserted.

    Q18. Explain stack operations: push, pop, and peek. Unit 2

    A Stack LIFO ADT supports three primary access methods, all of which run in **$O(1)$** time:

    • PUSH: Inserts an element on top of the stack.
      Check: Check if stack is full (top == MAX_SIZE - 1) to prevent Stack Overflow.
      Action: Increment top pointer, then assign value: top = top + 1, stack[top] = val.
    • POP: Removes and returns the element currently at the top of the stack.
      Check: Check if stack is empty (top == -1) to prevent Stack Underflow.
      Action: Retrieve value, then decrement top pointer: val = stack[top], top = top - 1, return val.
    • PEEK: Returns the value of the top element *without* removing it.
      Action: Return stack[top].

            res.append(left[i]); i += 1

            res.append(right[j]); j += 1
    res.extend(left[i:])
    res.extend(right[j:])
    return res

Bubble sort has **$O(n^2)$** average and worst-case time complexity, but sorts in-place (**$O(1)$** space). Merge sort is extremely fast and scalable; Bubble sort is highly inefficient for large datasets.

    In Insertion Sort, the inner shifting loop only runs if arr[j] > key. If the array is nearly sorted, the condition is false almost immediately for every element, reducing shifts. The time complexity becomes linear **$O(n)$** in the best-case, making it faster than Quick Sort or Merge Sort for nearly-sorted data.

    Q42. Explain heap sort conceptually. Unit 3

    Heap Sort is an in-place, unstable algorithm that works in two phases:

    1. Build Max Heap: Reorganize the unsorted array into a Max Heap (parent node >= children) in $O(n)$ time.
    2. Extract and Heapify: The root index 0 contains the largest element. Swap it with the last element in the heap, decrease the heap boundary by 1, and down-heapify the root node. Repeat until the array is fully sorted in $O(n \log n)$ time.

    Q46. Define tree, root, parent, child, sibling, leaf, level, height, and depth. Unit 4

    A Tree is a non-linear, hierarchical data structure of nodes connected by directed edges, forming no cycles.

    • Root: The unique topmost node with no parent.
    • Parent: A node that has an edge leading to one or more children.
    • Child: A node connected directly below a parent.
    • Sibling: Nodes that share the exact same parent node.
    • Leaf Node: A node with no children (terminal node, left and right are NULL).

    • Depth of a Node: The number of edges from the root to that node.
    • Height of a Node: The number of edges on the longest downward path from that node to a leaf. (Height of tree = height of root node).

    Q55. Explain BST deletion cases: leaf node, one-child node, and two-child node. Unit 4

    Deleting a node from a BST is divided into three logical cases depending on node child density:

    • Case 1: Leaf Node (0 children)
      Action: Simply remove the node and update its parent's pointer to NULL.
    • Case 2: Exactly One Child
      Action: Bypass the node. Link the parent node directly to the child of the deleted node, then free the deleted node.
    • Case 3: Two Children
      Action: Replace the value of the node with its Inorder Successor (smallest node in the right subtree) or Inorder Predecessor (largest node in the left subtree), and recursively delete that successor/predecessor node.
    Q56. Explain why BST search may become O(n) in the worst case. Unit 4

    The standard BST search takes $O(h)$ operations, where $h$ is the height of the tree. If elements are inserted in **sorted ascending or descending order** (e.g., [10, 20, 30, 40]), the tree degenerates into a **skewed binary tree** (like a singly linked list). In this skewed tree, each parent node has only 1 child, pushing the height $h$ to $n$. Searching or inserting now requires traversing the entire depth, resulting in a worst-case time complexity of **$O(n)$**.

    Q57. Define AVL tree and balance factor. Unit 4
    An AVL Tree is a self-balancing Binary Search Tree (BST) where the difference in heights of the left and right subtrees (the Balance Factor) of any node is at most 1, guaranteeing $O(\log n)$ search, insertion, and deletion times.

    The Balance Factor (BF) of a node is calculated as:

    $BF = ext{Height}( ext{Left Subtree}) - ext{Height}( ext{Right Subtree})$

    AVL Balanced Condition: For every single node: $$BF \in \{-1, 0, +1\}$$

    Q58. Explain AVL rotations: LL, RR, LR, and RL with examples. Unit 4

    There are four types of rotations used to restore balance in an AVL tree:

    1. Left-Left (LL) Case: Insertion in the left subtree of the left child.
      Resolution: Single Right Rotation around the parent.
    2. Right-Right (RR) Case: Insertion in the right subtree of the right child.
      Resolution: Single Left Rotation around the parent.
    3. Left-Right (LR) Case: Insertion in the right subtree of the left child.
      Resolution: Double Rotation: Left Rotation on left child, then Right Rotation on parent.
    4. Right-Left (RL) Case: Insertion in the left subtree of the right child.
      Resolution: Double Rotation: Right Rotation on right child, then Left Rotation on parent.

    A priority queue requires frequent insert and extract-max operations. This is significantly faster than using sorted arrays (which take $O(n)$ insert) or unsorted arrays (which take $O(n)$ extract).
