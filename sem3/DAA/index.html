Q1 (a). Solve the following recurrence relations using the Master Theorem:
(i) T(n) = 2T(n/2) + n   •   (ii) T(n) = 4T(n/2) + n²

▼

Part (i) Detailed Solution for T(n) = 2T(n/2) + n

2.5 Marks

1. Standard Master Theorem Form:

T(n) = a · T(n/b) + f(n), where a ≥ 1, b > 1, f(n) is asymptotically positive. Here: a = 2, b = 2, f(n) = n.

2. Compute Critical Exponent log_b(a):

log_b(a) = log_2(2) = 1 ⟹ n^(log_b(a)) = n^1 = n

3. Compare f(n) with n^(log_b(a)):

Here, $f(n) = n$ and $n^{\log_b a} = n$. Thus, $f(n) = \Theta(n^{\log_b a}) = \Theta(n)$.

4. Applicable Case: Master Theorem Case 2 (Balanced Work):

When $f(n) = \Theta(n^{\log_b a} \cdot \log^k n)$ with $k = 0$:

$$T(n) = \Theta(n^{\log_b a} \cdot \log^{k+1} n) = \Theta(n^1 \cdot \log^{0+1} n) = \mathbf{\Theta(n \log n)}$$

Conclusion: Part (i) represents standard Merge Sort divide-and-conquer recurrence, yielding $\Theta(n \log n)$.

2.5 Marks

1. Standard Form Parameters:

T(n) = 4T(n/2) + n² ⟹ a = 4, b = 2, f(n) = n²

2. Compute Critical Exponent:

log_b(a) = log_2(4) = 2 ⟹ n^(log_b a) = n^2

3. Compare f(n) with n^(log_b a):

Here, $f(n) = n^2$ and $n^{\log_b a} = n^2$. Thus, $f(n) = \Theta(n^{\log_b a}) = \Theta(n^2)$.

4. Applicable Case: Master Theorem Case 2:

$$T(n) = \Theta(n^{\log_b a} \cdot \log n) = \Theta(n^2 \log n) = \mathbf{\Theta(n^2 \log n)}$$

Mid-Term Q1(c) 2.5 Marks External Sorting Comparison CO2 [L4]

Q1 (c). Why is Merge Sort preferred over Quick Sort for external sorting?

▼

Systematic Technical Rationale (Exam Answer)

2.5 Marks

External sorting deals with data sets that cannot fit into main RAM memory and reside on secondary storage devices (hard drives, tapes, SSDs). Secondary storage exhibits huge random-access latency compared to sequential streaming. Merge Sort is universally preferred over Quick Sort for 4 fundamental architectural reasons:

1. Sequential Access vs Random Disk I/O

Merge Sort: Accesses data in strictly sequential streams. During the merge step, data is read sequentially block-by-block from sorted runs on disk and written sequentially to output. High disk throughput and minimal seek time.

Quick Sort: The partitioning step requires random bidirectional element swaps across the entire array span, triggering catastrophic disk seek latency (thrashing).

2. Guaranteed O(n log n) vs Worst-Case O(n²)

Merge Sort: Guarantees strict $\Theta(n \log n)$ time complexity across all inputs (best, average, worst). Predictable I/O run counts.

Quick Sort: Degenerates to $O(n^2)$ on unfavorable pivot selections (already sorted or repeated keys), leading to unacceptable disk operations for millions of records.

3. Natural Multi-Way Merging (k-Way Merge)

External Merge Sort effortlessly scales into k-way Merge Sort using a min-heap or tournament tree in RAM. $k$ sorted runs can be merged simultaneously into one run in $O(\log k)$ RAM work per element.

4. Stability & Hardware Compatibility

Merge Sort is inherently stable (preserves original order of equal keys). Furthermore, sequential streaming allows pipelined reading and asynchronous double buffering, overlapping CPU work with disk I/O.

1. Problem Definition & Greedy Choice Property

2 Marks

Problem Statement: Given a set of $n$ activities $S = \{A_1, \dots, A_n\}$ where each activity $A_i$ has a start time $s_i$ and finish time $f_i$ ($s_i < f_i$). Algorithm: Greedy-Activity-SelectorPseudocode
Algorithm ActivitySelector(s, f, n)
1   // Sort activities such that f[1] ≤ f[2] ≤ ... ≤ f[n]

Core Properties of an Algorithm (Knuth's 5 Criteria)

According to Donald Knuth, an algorithm must satisfy five fundamental criteria:

  1. Input: An algorithm has zero or more externally supplied quantities.
  2. Output: An algorithm produces at least one result or quantity that has a specific relation to the inputs.
  3. Definiteness: Each instruction must be clear, unambiguous, and precisely defined (no vague interpretations).
  4. Finiteness: The algorithm must terminate after a finite number of steps for all valid input cases.
  5. Effectiveness: Every instruction must be sufficiently basic that it can be carried out mechanically in finite time using pencil and paper.

Concrete Example — Euclid's Algorithm for GCD(a, b):

Euclid's GCD AlgorithmPseudocode 
Algorithm GCD(a, b)
    while b ≠ 0 do
        r ← a mod b
        a ← b
        b ← r
    end while
    return a
  • Input: Two positive integers $a, b$.
  • Output: Greatest Common Divisor integer.
  • Definiteness: Modulo and assignment are completely deterministic.
  • Finiteness: In each step $a \bmod b < b$, so the sequence of remainders strictly decreases to 0 within finite iterations.
  • Effectiveness: Integer division and remainder are elementary arithmetic operations.

The 6 Standard Steps of Algorithm Engineering

  1. Understand the Problem: Formulate inputs, outputs, exact domain constraints, and special boundary edge cases.
  2. Ascertain Computational Capabilities: Determine target hardware (sequential RAM model, parallel threads, secondary memory, distributed).
  3. Choose Design Paradigm & Data Structures: Select an optimal design technique (Divide & Conquer, Greedy, Dynamic Programming, Backtracking) and choose appropriate representations (arrays, hash tables, heaps, graphs).

Core Attributes of High-Quality Algorithms

  • Correctness: Produces mathematically sound outputs for all valid inputs and terminates reliably without infinite loops.
  • Time Efficiency: Minimal CPU instruction count and growth rate for large $n$ (prefer $O(n \log n)$ over $O(n^2)$).

Unit 1 • Short Ans Q5 2-3 Marks Time & Space Complexity Definitions

Q5. Define time complexity and space complexity.

▼

Formal Academic Definitions

Time Complexity: The time complexity of an algorithm $T(n)$ is a mathematical function that quantifies the total number of elementary computational steps (comparisons, arithmetic operations, assignments) executed by the algorithm as a function of the input size $n$. Because actual CPU wall-clock runtime varies with hardware, time complexity measures operations independent of machine architecture using asymptotic notations ($O, \Omega, \Theta$).

Space Complexity: The space complexity $S(n)$ of an algorithm is the total amount of memory storage required to execute and run to completion as a function of input size $n$. It is partitioned into:

S(n) = Fixed Space Component (c) + Variable / Auxiliary Space Component S_v(n)

where fixed space covers code storage and constant variables, while variable space covers dynamically allocated data structures, recursion call stacks, and buffer arrays.

Unit 1 • Short Ans Q6 2-3 Marks Best-Case Significance & Examples

Q6. What is the significance of the best-case time complexity? Can you give an example of an algorithm with different best-case and worst-case time complexities?

▼

Significance & Concrete Algorithm Example

Significance: Best-case time complexity defines the theoretical minimum amount of computational work an algorithm requires for an optimal input configuration. While worst-case provides guarantees, best-case reveals adaptive potential — whether an algorithm can terminate early on nearly-sorted data or quick lookups.

Example — Insertion Sort:

  • Best Case ($\Omega(n)$): Input array is already sorted in ascending order. The inner while loop test fails on the very first comparison for every element $i$. Only $n - 1$ total comparisons occur $\implies \mathbf{\Theta(n)}$ linear time.
  • Worst Case ($O(n^2)$): Input array is sorted in reverse order. Every new element must shift past all previously sorted elements, yielding $\sum_{i=1}^{n-1} i = \frac{n(n-1)}{2} \implies \mathbf{\Theta(n^2)}$ quadratic time.

Alternative Example: Linear Search — Best case is $O(1)$ when target is at index 1; Worst case is $O(n)$ when target is at index $n$ or absent.

Unit 1 • Short Ans Q7 2-3 Marks Space Complexity Components

Q7. What is the significance of analyzing the space complexity of an algorithm? Explain the components of space complexity. Provide an example where space complexity is crucial.

▼

Components & Practical Importance

Significance: In memory-constrained systems (embedded microcontrollers, mobile devices, IoT, big data streaming), excessive memory usage leads to Out-Of-Memory crashes, disk swapping, and severe performance degradation.

Components of Space Complexity:

  1. Instruction / Fixed Space: Space needed to store compiled instructions, constant definitions, and simple variables. Fixed size independent of $n$.
  2. Data / Variable Space: Dynamically allocated memory proportional to input size $n$ (arrays, matrices, nodes).
  3. Environment Stack Space (Recursion Overhead): Space required on the CPU call stack to store activation records (return address, local variables, parameters) for recursive calls. Proportional to recursion depth $O(\text{depth})$.

Example Where Space is Crucial — Merge Sort vs Quick Sort:

Merge Sort requires $O(n)$ auxiliary memory for merge buffer arrays. Sorting 100 GB of data in 16 GB of RAM causes memory exhaustion. In contrast, in-place Quick Sort requires only $O(\log n)$ stack space, making space complexity the deciding factor.

Unit 1 • Short Ans Q8 2-3 Marks Components of Time Complexity

Q8. Explain the components of time complexity.

▼

Breakdown of Algorithmic Time Components

The total time taken by an algorithm consists of two fundamental phases:

Total Time = Compile Time + Run Time (Execution Time)
  1. Compile Time: The time required by the compiler to translate high-level program code into machine bytecode or binary code. For a given program, compile time is fixed and independent of input data size $n$. Hence, algorithm analysis ignores compile time.
  2. Run Time (Execution Time): The operational time consumed while processing input size $n$. This is quantified by:
    • Basic Operations: The primary computational statements that dominate runtime (e.g., key comparisons in sorting, scalar multiplications in matrix multiplication).
    • Operation Frequency / Step Count: The exact count of times each basic operation executes as a function of $n$.
    • Unit Execution Cost ($c_i$): The constant CPU machine cycles consumed per instruction.

Q1. Write the asymptotic notations used for best case, average case and worst-case analysis. Write an algorithm for finding maximum element of an array and perform best, worst, and average case complexity.

▼

1. Asymptotic Notations ($O, \Omega, \Theta$) Formal Foundations

4 Marks
  • Big-Oh ($O$) — Asymptotic Upper Bound: $f(n) = O(g(n))$ if $\exists c > 0, n_0 \ge 1$ such that $0 \le f(n) \le c \cdot g(n)$ for all $n \ge n_0$. Standard notation for Worst-Case Analysis.
  • Big-Omega ($\Omega$) — Asymptotic Lower Bound: $f(n) = \Omega(g(n))$ if $\exists c > 0, n_0 \ge 1$ such that $0 \le c \cdot g(n) \le f(n)$ for all $n \ge n_0$. Standard notation for Best-Case Analysis and problem lower bounds.
  • Big-Theta ($\Theta$) — Asymptotically Tight Bound: $f(n) = \Theta(g(n))$ if $\exists c_1, c_2 > 0, n_0 \ge 1$ such that $c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$ for all $n \ge n_0$. Represents exact growth rate when upper and lower bounds coincide. Used in Average-Case Analysis.

2. Algorithm FindMax(A, n) & Complexity Analysis

6 Marks
Algorithm FindMax(A, n)Pseudocode 
Algorithm FindMax(A, n)
1   maxVal ← A[1]
2   for i ← 2 to n do
3       if A[i] > maxVal then
4           maxVal ← A[i]
5       end if
6   end for
7   return maxVal

Complexity Analysis:

  • Basic Operation: The comparison A[i] > maxVal in line 3.
  • Best-Case: Array is sorted in descending order (e.g. $[10, 8, 6, 4]$). The condition A[i] > maxVal is false for every $i \ge 2$. Line 4 (assignment) executes 0 times. However, line 3 still executes exactly $n - 1$ comparisons. Time Complexity $= \mathbf{\Omega(n)}$ (specifically $n - 1$ steps).
  • Worst-Case: Array is sorted in ascending order (e.g. $[4, 6, 8, 10]$). Line 3 comparison is true for every element, causing line 4 assignment to execute $n - 1$ times. Total comparisons $= n - 1$. Time Complexity $= \mathbf{O(n)}$.
  • Average-Case: Assuming all $n!$ permutations are equally likely, probability that $A[i]$ is a new maximum is $1/i$. Expected assignments $= \sum_{i=2}^n \frac{1}{i} = \ln n + \gamma - 1$. Total comparisons remains strictly $n - 1$. Time Complexity $= \mathbf{\Theta(n)}$.
Summary: Best Case = Ω(n), Worst Case = O(n), Average Case = Θ(n). Strictly Θ(n) comparisons across all inputs! Auxiliary space = O(1).

Unit 2 • SA-12-3 MarksDivide, Conquer, Combine

Q1. Explain the three steps of the divide-and-conquer strategy (divide, conquer, combine) with reference to Merge Sort.

▼
  1. Divide: Divide the problem into several smaller subproblems that are similar to the original problem. In Merge Sort: compute $mid = \lfloor (low + high)/2 \rfloor$ in $O(1)$ time, dividing the array $A[low..high]$ into two halves: $A[low..mid]$ and $A[mid+1..high]$.
  2. Conquer: Conquer the subproblems by solving them recursively. If the subproblem sizes are small enough (base case $low \ge high$, 1 element), solve them directly. In Merge Sort: recursively invoke MergeSort(A, low, mid) and MergeSort(A, mid+1, high).
  3. Combine: Combine the solutions of the subproblems into the solution for the original problem. In Merge Sort: invoke Merge(A, low, mid, high) which merges two sorted adjacent subarrays into a single sorted array in linear $O(n)$ time using two pointers.
Unit 2 • SA-22-3 MarksD&C vs Brute Force

Q2. Why is the divide-and-conquer paradigm considered more efficient than brute force for large problem sizes?

▼

Brute force algorithms typically consider all combinations or repeatedly compare all pairs, resulting in quadratic ($O(n^2)$) or exponential ($O(2^n)$) runtimes. In contrast, divide-and-conquer exponentially reduces problem scale at logarithmic depth ($\log n$).

  • Logarithmic Depth: Halving problem size creates a recursion tree of height $\log_2 n$.
  • Reduced Comparison Volume: For sorting, brute-force (Bubble/Selection) performs $\approx n^2 / 2$ comparisons. Merge Sort performs $n \log_2 n$. For $n = 1,000,000$, brute force requires $\approx 5 \times 10^{11}$ operations, whereas D&C requires only $\approx 2 \times 10^7$ operations — over 25,000 times faster.
  • Parallelizability: Independent subproblems can be solved concurrently across multiple CPU cores.

▼

In-Place Property: Quick Sort partitions and rearranges elements within the original array using pointer swaps (e.g. Lomuto or Hoare partitioning). 0/1 Knapsack: Items are indivisible ($x_i \in \{0, 1\}$). Taking a high-ratio item may leave empty capacity that cannot fit subsequent items. The lost capacity often outweighs the ratio advantage (empty space penalty), violating greedy choice.

Unit 2 • SA-142-3 MarksOverlapping Subproblems

Q14. What are overlapping subproblems? Illustrate with the computation of Fibonacci numbers.

▼

Overlapping Subproblems: A problem has overlapping subproblems if a recursive algorithm visits the same subproblems repeatedly rather than generating new subproblems at each step.

Fibonacci Example: Computing $Fib(5) = Fib(4) + Fib(3)$:

  • $Fib(4)$ calls $Fib(3)$ and $Fib(2)$.
  • $Fib(3)$ is computed twice independently.
  • $Fib(2)$ is computed 3 times, and $Fib(1)$ is computed 5 times.

Dynamic programming evaluates each distinct subproblem once and caches the result, reducing $O(2^n)$ work to $O(n)$.

▼

Q1. State and solve the 0/1 Knapsack Problem using Dynamic Programming. Explain why the Greedy approach fails for 0/1 Knapsack, derive the recurrence, and provide the complete tabular trace for W=8, w={3, 4, 6, 5}, p={2, 3, 1, 4}. Compare it with Fractional Knapsack.

▼

1. Problem Definition & Mathematical Formulation

2 Marks

0/1 Knapsack Formulation: We are given $n$ items, each with an integer weight $w_i > 0$ and integer profit $p_i > 0$, and a knapsack with maximum weight capacity $W$. We must select an assignment vector $x = \langle x_1, x_2, \dots, x_n \rangle$ where $x_i \in \{0, 1\}$ (each item is either completely chosen or completely left behind) to:

Maximize: ∑(i=1 to n) p_i · x_i Subject to: ∑(i=1 to n) w_i · x_i ≤ W, where x_i ∈ {0, 1}

Fractional Knapsack Formulation: Here, items can be broken down into fractions, meaning $x_i \in [0, 1]$. We can take an arbitrary fraction of an item if remaining capacity is less than its full weight.

2. Algorithmic Approach & Proof Why Greedy Fails on 0/1

4 Marks

Why Greedy Works for Fractional Knapsack: Fractional Knapsack exhibits the Greedy-Choice Property: sorting items by value-to-weight ratio $r_i = p_i / w_i$ in descending order and greedily filling capacity guarantees global optimality because the knapsack can always be filled to 100% capacity with the densest value density.

Why Greedy FAILS for 0/1 Knapsack (Classic Counterexample):

Counterexample Setup

Knapsack Capacity $W = 50$.

Item 1: $w_1 = 10, p_1 = 60 \implies r_1 = 6.0$/kg

Item 2: $w_2 = 20, p_2 = 100 \implies r_2 = 5.0$/kg

Item 3: $w_3 = 30, p_3 = 120 \implies r_3 = 4.0$/kg

Greedy vs Optimal Choice

Greedy Selection (by ratio): Takes Item 1 ($w=10, p=60$) + Item 2 ($w=20, p=100$). Remaining capacity = $20$. Cannot fit Item 3 ($w=30$). Greedy Profit = 160.

Optimal DP Selection: Takes Item 2 ($w=20, p=100$) + Item 3 ($w=30, p=120$). Total weight = $50 \le 50$. Optimal Profit = 220!

Conclusion: Empty space left by indivisible items penalizes the greedy heuristic. Therefore, 0/1 Knapsack requires Dynamic Programming with Bellman's principle of optimality.

Bellman Recurrence Relation (Class Note #4):

M[i, w] = M[i-1, w] if w_i > w (Cannot fit item i) M[i, w] = max( M[i-1, w], M[i-1, w - w_i] + p_i ) if w_i ≤ w (Exclude vs Include) Base Cases: M[0, w] = 0 for all w; M[i, 0] = 0 for all i

3. Tabular Dynamic Programming Pseudocode

4 Marks
Algorithm: 0/1 Knapsack Bottom-Up Tabulation Python 3 / Pseudocode 
def knapsack_01(n: int, W: int, weights: list, profits: list):
    # dp[i][w] = maximum profit using a subset of items 1..i with capacity w
    dp = [[0] * (W + 1) for _ in range(n + 1)]
    
    for i in range(1, n + 1):
        wi = weights[i - 1]
        pi = profits[i - 1]
        for w in range(1, W + 1):
            if wi > w:
                dp[i][w] = dp[i - 1][w]
            else:
                dp[i][w] = max(dp[i - 1][w], dp[i - 1][w - wi] + pi)
                
    max_profit = dp[n][W]
    
    # Backtrack to identify selected items
    selected_items = []
    curr_w = W
    for i in range(n, 0, -1):
        if dp[i][curr_w] != dp[i - 1][curr_w]:
            selected_items.append(i) # Item i was included
            curr_w -= weights[i - 1]
            
    return max_profit, selected_items

5. Asymptotic Time & Space Complexity Analysis

4 Marks
  • Time Complexity: Filling an $(n + 1) \times (W + 1)$ table where each cell computes an $O(1)$ max operation takes $\mathbf{O(n \cdot W)}$ time. Backtracking takes $O(n)$ time. Total Time = $\mathbf{O(n \cdot W)}$.

Q2. State the Master Theorem for Divide-and-Conquer Recurrences with all 3 cases and its logarithmic extension. Solve MergeSort, Binary Search, Strassen's Matrix Multiplication, and Karatsuba's Algorithm. Explain when the Master Theorem FAILS and provide the loop complexity rules from class notes.

1. Standard Recurrence Form & Recursion Tree Model

2 Marks

Divide-and-Conquer algorithms partition a problem of size $n$ into $a$ subproblems, each of size $n/b$, with $f(n)$ work spent outside the recursive calls (partitioning and combining). The recurrence is expressed as:

T(n) = a · T(n / b) + f(n) where a ≥ 1, b > 1, and f(n) is asymptotically positive

The recursion tree has depth $\log_b n$ and the number of leaves at the deepest level is $a^{\log_b n} = n^{\log_b a}$. The core intuition of Master Theorem is a "tug-of-war" between the work done at the leaf nodes ($\Theta(n^{\log_b a})$) and the work done at the root ($f(n)$).

2. Formal Statement of Master Theorem (All 3 Cases + Extension)

4 Marks

Let $c_{crit} = \log_b a$. We compare $f(n)$ asymptotically with the watershed function $n^{\log_b a}$:

  • Case 1 (Leaves Dominate): If $f(n) = O(n^{\log_b a - \epsilon})$ for some constant $\epsilon > 0$ (i.e. $f(n)$ is polynomially smaller than $n^{\log_b a}$), then:
    $$T(n) = \Theta(n^{\log_b a})$$
  • Case 2 (Equal Work Distribution Across Tree Levels): If $f(n) = \Theta(n^{\log_b a})$, then work is distributed equally across all $\log_b n$ levels:
    $$T(n) = \Theta(n^{\log_b a} \cdot \log n)$$
    Extended Case 2 (Logarithmic factors): If $f(n) = \Theta(n^{\log_b a} \cdot \log^k n)$ for $k \ge 0$, then:
    $$T(n) = \Theta(n^{\log_b a} \cdot \log^{k+1} n)$$
  • Case 3 (Root Dominates): If $f(n) = \Omega(n^{\log_b a + \epsilon})$ for some constant $\epsilon > 0$ AND satisfies the regularity condition $a \cdot f(n/b) \le c \cdot f(n)$ for some $c < 1$ and all large $n$, then:
    $$T(n) = \Theta(f(n))$$

4. Fallacy Analysis: When Master Theorem FAILS

4 Marks

The Master Theorem does not apply in 4 specific failure modes:

  1. Non-Polynomial Gap: $T(n) = 2T(n/2) + n / \log n$. Here $\log_b a = 1 \implies n^{\log_b a} = n$. The ratio is $n / (n / \log n) = \log n$. Although $f(n)$ is smaller than $n$, it is not polynomially smaller (no constant $\epsilon > 0$ satisfies $n / \log n = O(n^{1 - \epsilon})$). Master Theorem fails! Solution via Recursion Tree: $T(n) = \Theta(n \log \log n)$.
  2. Non-Constant Subproblem Division: $T(n) = T(n-1) + n$ (e.g., Insertion Sort). Here size decreases by subtraction, not division by a constant factor $b > 1$.
  3. Varying Subproblem Sizes: $T(n) = T(n/3) + T(2n/3) + n$ (Akra-Bazzi method required instead).
  4. Violation of Regularity Condition in Case 3: $T(n) = 2T(n/2) + n(2 - \cos n)$. Oscillating function violates regularity condition $a \cdot f(n/b) \le c \cdot f(n)$.

Q3. Explain the Backtracking paradigm using the N-Queens Problem. Formulate the non-attacking bounding conditions (row, column, and diagonal). Draw the complete State-Space Tree for the 4-Queens Problem and write the algorithm with asymptotic complexity.

▼

1. Problem Definition & Mathematical Formulation

2 Marks

The N-Queens Problem requires placing $N$ non-attacking chess queens on an $N \times N$ chessboard such that no two queens threaten each other. In chess, a queen attacks any piece in the same row, same column, or along any diagonal.

Representation Vector: Since every row must contain exactly one queen, we can represent a solution as an $N$-tuple $X = (x_1, x_2, \dots, x_N)$, where $x_i \in \{1, 2, \dots, N\}$ indicates the column index of the queen placed in row $i$.

2. Backtracking Paradigm vs. Brute Force Search

4 Marks
  • Naive Brute Force: Placing $N$ queens randomly on $N^2$ squares takes $\binom{N^2}{N}$ states. For $N=8$, $\binom{64}{8} \approx 4.4 \times 10^9$ states!
  • One-Queen-Per-Row Heuristic: Placing one queen per row gives $N^N$ states ($8^8 = 16,777,216$ states).
  • Permutation Generator: Ensuring no two queens share the same column restricts states to $N!$ ($8! = 40,320$ states).
  • Backtracking (Pruned Depth-First Search): Backtracking incrementally constructs a solution vector $X$. At row $k$, if placing a queen at column $x_k$ violates any bounding condition with previously placed queens $(x_1, \dots, x_{k-1})$, the algorithm prunes the entire subtree immediately and backtracks to row $k-1$. For $N=8$, only $2,057$ nodes are visited, a massive efficiency jump!

3. Mathematical Diagonal Invariant & Bounding Functions

4 Marks

Two queens placed at coordinates $(r_1, c_1)$ and $(r_2, c_2)$ are in conflict if and only if:

  1. Same Column: $c_1 = c_2$
  2. Same Major Diagonal (\): The slope is $+1$, which means $(r_1 - c_1) = (r_2 - c_2) \implies r_1 - r_2 = c_1 - c_2$.
  3. Same Minor Diagonal (/): The slope is $-1$, which means $(r_1 + c_1) = (r_2 + c_2) \implies r_1 - r_2 = c_2 - c_1$.

Combined Absolute Condition: Two queens placed at rows $i$ and $k$ with columns $x_i$ and $x_k$ conflict along a diagonal if:

|i - k| = |x_i - x_k|

O(1) Bounding Check via Boolean Tracking Arrays: Instead of looping through all previous queens, we can use three boolean lookup arrays: col[c], diag1[r - c + N - 1], and diag2[r + c], enabling instantaneous $O(1)$ safety verification!

5. Algorithm Implementation & Complexity Bounds

4 Marks
Algorithm: N-Queens Backtracking with O(1) Sets Python 3 
def solveNQueens(n: int):
    solutions = []
    board = [-1] * n
    cols = set()
    diag1 = set() # r - c
    diag2 = set() # r + c
    
    def backtrack(r: int):
        if r == n:
            solutions.append(list(board))
            return
            
        for c in range(n):
            if c in cols or (r - c) in diag1 or (r + c) in diag2:
                continue # Prune invalid branch
                
            # Place Queen
            board[r] = c
            cols.add(c)
            diag1.add(r - c)
            diag2.add(r + c)
            
            backtrack(r + 1)
            
            # Backtrack state unwind
            cols.remove(c)
            diag1.remove(r - c)
            diag2.remove(r + c)
            board[r] = -1
            
    backtrack(0)
    return solutions
  • Time Complexity: Upper bound is $O(N!)$ because the first row has $N$ options, second at most $N-1$, etc. With aggressive diagonal pruning, effective runtime is dramatically lower, but asymptotic worst-case remains $\mathbf{O(N!)}$.
  • Auxiliary Space Complexity: $\mathbf{O(N)}$ for the recursion call stack (depth $N$) and the board / diagonal tracking sets.

1. Problem Statement & Arithmetic Cost

Given a sequence of $n$ matrices $\langle A_1, A_2, \dots, A_n \rangle$ where matrix $A_i$ has dimensions $p_{i-1} \times p_i$, matrix multiplication is associative ($A(BC) = (AB)C$) but the number of scalar multiplications depends heavily on parenthesization.

2. Optimal Substructure & Recurrence

4 Marks

Let $m[i, j]$ be the minimum number of scalar multiplications needed to compute $A_i \dots A_j$. Any optimal parenthesization splits the chain at some index $k$ ($i \le k < j$): $(A_i \dots A_k)(A_{k+1} \dots A_j)$.

m[i, j] = 0 if i = j m[i, j] = min_{i ≤ k < j} { m[i, k] + m[k+1, j] + p_{i-1} · p_k · p_j } if i < j

Q5. Define Minimum Spanning Tree (MST) and prove the Cut Property. Contrast Kruskal's Algorithm (with Disjoint Set Union) and Prim's Algorithm (with Min-Heap). Trace both on a weighted graph and discuss performance on sparse vs dense graphs.

1. MST Definition & Cut Property Theorem

4 Marks

Given an undirected connected weighted graph $G = (V, E, w)$, a Spanning Tree is an acyclic subgraph $T \subseteq E$ containing all $|V|$ vertices with $|V|-1$ edges. A Minimum Spanning Tree minimizes $\sum_{e \in T} w(e)$.

The Cut Property: Let $S \subset V$ be any cut partitioning vertices into $S$ and $V - S$. If an edge $e = (u, v)$ crosses the cut ($u \in S, v \in V - S$) and has strictly minimum weight among all crossing edges, then $e$ must belong to every MST of $G$.

2. Kruskal's vs. Prim's Comprehensive Comparison

8 Marks
Dimension Kruskal's Algorithm Prim's Algorithm
Greedy Strategy Edge-based: Sorts edges globally, greedily adds smallest edge if no cycle. Vertex-based: Grows a single connected tree outwards from an arbitrary root.
Cycle Detection Uses Disjoint Set Union (DSU) with Union-by-Rank & Path Compression. Inherently acyclic because it only adds edges between $S$ and $V-S$.

1. Divide & Conquer Strategy & Strip Bound Proof

6 Marks

Given $n$ points in a 2D plane, finding the pair with minimum Euclidean distance $d(p_i, p_j)$ takes $O(n^2)$ by brute force. Divide & Conquer achieves $O(n \log n)$:

  1. Sort points by x-coordinate into $P_x$ and y-coordinate into $P_y$ in $O(n \log n)$.
  2. Divide: Split at vertical median line $L: x = x_{mid}$ into left half $Q$ and right half $R$.

  5. The 7-Point Geometric Proof: In the strip, consider a rectangle of width $2\delta$ and height $\delta$. Each half ($\delta \times \delta$) can contain at most 4 points without violating the invariant that any two points in the same half are at least $\delta$ apart. Thus, for any point $p$, at most 7 other points in the y-sorted strip need to be checked!

Q7. Prove that any comparison-based sorting algorithm requires Ω(n log n) operations in the worst case using a Decision Tree model. Compare MergeSort, QuickSort, HeapSort, Counting Sort, and Radix Sort in terms of time, space, and stability.

▼

1. Decision Tree Lower Bound Proof

4 Marks

In any comparison-based sort, every execution traces a path from the root to a leaf in a binary decision tree where internal nodes represent comparisons $a_i \le a_j$.

  • For $n$ distinct elements, there are $n!$ possible permutations. Each permutation must correspond to at least one reachable leaf to guarantee correctness $\implies \text{Leaves } L \ge n!$.
  • A binary tree of height $h$ has at most $2^h$ leaves $\implies 2^h \ge L \ge n! \implies h \ge \log_2(n!)$.
  • By Stirling's approximation, $\log_2(n!) = \sum_{i=1}^n \log_2 i \ge \sum_{i=n/2}^n \log_2(n/2) = \frac{n}{2} \log_2(n/2) = \mathbf{\Omega(n \log n)}$.
  • Hence, no comparison sort can run faster than $\mathbf{\Omega(n \log n)}$ in the worst case.

Module 1.1

Mathematical Foundations, Asymptotic Limits & Growth Hierarchy

↓

Algorithm analysis quantifies resource consumption (time steps and memory words) as a function of input size $n \to \infty$. By abstracting away machine constants, asymptotic notations provide hardware-independent performance guarantees.

Limit Theorem for Asymptotic Classification:
L = lim_{n &to; ∞} [ f(n) / g(n) ]
• L = 0 ⇒ f(n) = o(g(n)) [Strict Upper Bound]
• 0 < L < ∞ ⇒ f(n) = Θ(g(n)) [Asymptotically Tight Bound]
• L = ∞ ⇒ f(n) = ω(g(n)) [Strict Lower Bound]
Formal Big-O ($O$) Definition

$f(n) = O(g(n))$ if $\exists c > 0, n_0 \ge 1$ such that $0 \le f(n) \le c \cdot g(n)$ for all $n \ge n_0$. Represents an asymptotic upper bound (worst-case ceiling).

Formal Big-Omega ($\Omega$) Definition

$f(n) = \Omega(g(n))$ if $\exists c > 0, n_0 \ge 1$ such that $0 \le c \cdot g(n) \le f(n)$ for all $n \ge n_0$. Represents an asymptotic lower bound (algorithmic floor).

Formal Big-Theta ($\Theta$) Definition

$f(n) = \Theta(g(n))$ if $\exists c_1, c_2 > 0, n_0 \ge 1$ such that $c_1 g(n) \le f(n) \le c_2 g(n)$ for all $n \ge n_0$. True if and only if $f(n) = O(g(n))$ AND $f(n) = \Omega(g(n))$.

Universal Asymptotic Growth Hierarchy:

O(1) < O(log log n) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2&supn;) < O(e&supn;) < O(n!) < O(n&supn;)

Classroom Rules for Loop Complexity (Direct from Class Note #1):

  • Single Loop: for i = 1 to n do ... → Executes $n$ times → $O(n)$.
  • Nested Loops: for i = 1 to n do for j = 1 to n do ... → Executes $n \times n = n^2$ times → $O(n^2)$.
  • Sequential Loops: Two successive non-nested loops of size $n$ → $n + n = 2n$ → $O(n)$.
  • Three-Level Nested Loops: for i ... for j ... for k ... → $n \times n \times n = n^3$ times → $O(n^3)$.
Module 1.2

Recurrence Relations & Master Theorem Framework

↓

Divide-and-conquer algorithms generate recursive runtimes characterized by the recurrence $T(n) = a T(n/b) + f(n)$, where $a \ge 1$ is the number of subproblems, $b > 1$ is the subproblem reduction factor, and $f(n)$ represents partition and combination overhead.

Standard Master Recurrence: T(n) = a · T(n/b) + Θ(n^k · log^p n)
Critical Watershed Exponent: c_{crit} = log_b(a)
• Case 1 (Leaves Dominate): c_{crit} > k ⇒ T(n) = Θ(n^{log_b a})
• Case 2 (Balanced Work): c_{crit} = k ⇒ T(n) = Θ(n^k · log^{p+1} n)
• Case 3 (Root Dominates): c_{crit} < k AND regularity a · f(n/b) ≤ c · f(n) ⇒ T(n) = Θ(n^k · log^p n)

Primary Solving Methods:

  1. Substitution Method: Formulate a mathematical guess for $T(n)$, then establish the inductive step and verify boundary conditions for $n \ge n_0$.
  2. Recursion Tree Method: Expand the recurrence into a tree of depth $\log_b n$. Compute work at level $i$: $a^i f(n/b^i)$. Sum across all levels from $i=0$ to $\log_b n$.
  3. Master Theorem: Algebraic formula delivering instant closed-form asymptotic bounds when subproblem branches shrink by a constant factor.
• Non-Applicable Pitfall: T(n) = 2T(n/2) + n / log n
Here log_2(2) = 1 and f(n) = n / log n. The ratio f(n) / n^{log_b a} = 1 / log n is asymptotically smaller than n^1, but NOT polynomially smaller (no positive ε exists such that n / log n = O(n^{1 - ε})). Master Theorem does NOT apply! (Solved via recursion tree to Θ(n log log n)).
Module 1.3

Comparison-Sort Lower Bound & Linear-Time Sorting Algorithms

↓

Any sorting algorithm that operates exclusively by pairwise comparison operations ($A[i] \le A[j]$) can be modeled as a binary decision tree. For $n$ distinct keys, there are $n!$ possible permutations, requiring at least $n!$ distinct leaf nodes.

Binary Tree Depth Invariant: 2^h ≥ L ≥ n!
h ≥ log_2(n!) = ∑_{i=1}^n log_2 i ≥ ∫_1^n log_2 x dx = Ω(n log n)
Therefore, no comparison-based sort can beat Ω(n log n) in the worst-case!
Counting Sort • $O(n + k)$

Non-comparison integer sorting. Counts occurrences of each value in range $[0, k]$, constructs prefix sums to determine exact output positions. Stable, requires $O(n + k)$ auxiliary space.

Radix Sort • $O(d(n + k))$

Sorts elements digit-by-digit from Least Significant Digit (LSD) to Most Significant Digit (MSD) using Counting Sort as an intermediate subroutine. Invariant: Stability of digit sort preserves relative ordering of preceding digits.

Heap Sort • $O(n \log n)$

Builds Max-Heap in $O(n)$ time via bottom-up sift-down, then repeatedly extracts max and places it at the end in $O(\log n)$ per element. In-place $O(1)$ auxiliary memory, but unstable due to long-range child swaps.

Module 1.4

Searching Algorithms & Universal Hashing Systems

↓

Searching locates target keys in structured or unstructured data collections. While Binary Search halves the search space each step, Interpolation Search mirrors human phone-book lookups by probing based on numerical key distribution.

Interpolation Search Probe Formula:
pos = low + ⌊ [ (key - A[low]) / (A[high] - A[low]) ] × (high - low) ⌋
• Average Case: O(log log n) on uniformly distributed data.
• Worst Case: O(n) when keys grow exponentially (e.g., [1, 2, 4, 8, 16, 32, ...]).

Hashing Collisions & Resolution Paradigms:

  • Chaining: Each table slot heads a linked list. Average search cost is $O(1 + \alpha)$ where load factor $\alpha = n / m$.
  • Open Addressing - Linear Probing: $h(k, i) = (h'(k) + i) \bmod m$. Suffers from primary clustering (long contiguous runs of occupied slots).
  • Open Addressing - Quadratic Probing: $h(k, i) = (h'(k) + c_1 i + c_2 i^2) \bmod m$. Eliminates primary clustering; mild secondary clustering.
  • Double Hashing: $h(k, i) = (h_1(k) + i \cdot h_2(k)) \bmod m$. Provides permutation of all slots if $\gcd(h_2(k), m) = 1$. Optimal open addressing.
Universal Hashing Family &H;_{p, m}:
Choose prime p > m. Let h_{a, b}(x) = ((a · x + b) mod p) mod m for a ∈ {1, ..., p-1}, b ∈ {0, ..., p-1}.
Collision Property: ∀ x ≠ y, Pr_{h ∈ &H;}[ h(x) == h(y) ] ≤ 1/m.
Guarantees expected O(1) operations irrespective of any adversarial input sequence!
Module 1.5

Amortized Analysis: Aggregate, Accounting & Potential Method Φ

↓

Amortized analysis guarantees the average performance of each operation over a worst-case sequence of operations. Unlike average-case analysis, no probability distribution over inputs is assumed.

1. Aggregate Method

Computes the total worst-case cost $T(n)$ across the entire sequence of $n$ operations, then assigns the amortized cost $\hat{c} = T(n) / n$ equally to each operation.

2. Accounting (Banker's) Method

Assigns an artificial charge $\hat{c}_i$ to each operation. If $\hat{c}_i > c_i$, excess is stored as credit on specific data items. Credit must remain $\ge 0$ at all times to fund costly future operations.

3. Potential (Physicist's) Method

Defines potential function $\Phi(D_i)$ mapping data structure state $D_i$ to a real number. Amortized cost: $\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1})$. If $\Phi(D_n) \ge \Phi(D_0)$, total amortized upper-bounds total real cost.

Dynamic Table Doubling Proof via Potential Method Φ:
Let Φ(D_i) = 2 · num_i - size_i, where num_i is element count and size_i is array capacity.
• Immediately after doubling: size = 2 × num ⇒ Φ = 2(num) - 2(num) = 0.
• When full (ready to double): size = num ⇒ Φ = 2(num) - num = num.
• Normal Insertion (no resize): c_i = 1, ΔΦ = (2(num+1) - size) - (2(num) - size) = 2.
&hat;c_i = 1 + 2 = 3.
• Doubling Insertion (num == size): c_i = num + 1 (copy num elements + 1 insert).
Old Φ = num. New size = 2 · num. New Φ = 2(num+1) - 2 · num = 2.
ΔΦ = 2 - num. &hat;c_i = (num + 1) + (2 - num) = 3.
Result: Every insert operation has amortized cost strictly ≤ 3 ⇒ O(1) amortized!
Module 1.6

Randomised Algorithms: Monte Carlo, Las Vegas & Karger's Min-Cut

↓

Randomised algorithms utilize a source of pseudo-random coin flips during execution. They thwart worst-case adversary inputs and are classified into two complementary families:

Las Vegas Algorithms

Always outputs the correct answer. Running time is a random variable. Examples: Randomized QuickSort (expected $O(n \log n)$), Randomized QuickSelect (expected $O(n)$ order statistics).

Monte Carlo Algorithms

Running time is deterministic. Output has a bounded probability of error ($P_{\text{err}} \le \epsilon$). Confidence can be amplified arbitrarily close to 1 by repeating independent trials. Examples: Karger's Min-Cut, Miller-Rabin Primality.

Karger's Contraction Algorithm for Global Min-Cut:
Given multigraph G=(V, E). Repeatedly pick random edge (u, v) and contract vertices u and v until 2 meta-vertices remain.
Min-Cut Size: k. Min degree of any vertex ≥ k ⇒ |E| ≥ n · k / 2.
Pr[Random edge belongs to min-cut] ≤ k / |E| ≤ k / (nk/2) = 2/n.
Pr[Min-cut survives step 1] ≥ 1 - 2/n = (n-2) / n.
Overall Survival Probability:
P_{success} ≥ ∏_{i=0}^{n-3} [ (n - i - 2) / (n - i) ] = (2) / (n(n - 1)) = 1 / 𝒞(n, 2) ≈ 2 / n².
By repeating N = 𝒞(n, 2) · ln(1/δ) trials, min-cut is found with probability ≥ 1 - δ in O(n² log n) time.
Module 1.7

Cache-Aware Architecture & Cache-Oblivious Model

↓

Modern microprocessors are orders of magnitude faster than main memory (RAM). Memory hierarchy bridges this speed gap through tiered caches governed by spatial and temporal locality.

Memory Latency Cliff

CPU Registers (< 1 ns) → L1 Cache (~1 ns, 32-64KB) → L2 Cache (~3-4 ns, 512KB) → L3 Cache (~15 ns, 16-64MB) → Main DRAM (~60-100 ns). Accessing RAM causes a 100x latency stall.

Cache Line & Locality

Data moves in fixed 64-byte blocks (cache lines). Spatial locality: Accessing consecutive array elements. Temporal locality: Reusing the same memory address within a short time window.

The 3 C's of Cache Misses

1. Compulsory (Cold): First access to a block. 2. Capacity: Working set exceeds cache size. 3. Conflict: Multiple active blocks map to the same set (set-associative).

Cache-Oblivious Model (Frigo, Leiserson, Prokop, Ramachandran, 1999):
Analyzes algorithms under parameters M (cache size) and B (cache line block size) WITHOUT the code knowing M or B!
• Standard Loop Matrix Transpose: Causes O(N²) cache misses if column stride exceeds cache size.
• Cache-Oblivious Recursive Divide-and-Conquer Transpose:
Recursively partition N × N matrix into four (N/2) × (N/2) blocks.
Once subproblem size N × N fits inside cache (≤ α M), ALL remaining operations hit in cache!
Achieves optimal cache miss bound: Q(N) = O(1 + N² / B), optimal across ALL hierarchy tiers simultaneously!

Module 2.1

Divide & Conquer Foundations: Closest Pair & Convex Hull Graham Scan

↓

Divide-and-conquer decomposes a problem into disjoint subproblems of identical type, solves them recursively, and combines the sub-solutions. It achieves optimal $O(n \log n)$ bounds for fundamental computational geometry problems.

Closest Pair of Points in 2D • $O(n \log n)$

Divide points by vertical median $x$-line. Recursively find minimum distance $\delta = \min(\delta_L, \delta_R)$. In the boundary strip $[x_{mid} - \delta, x_{mid} + \delta]$, any rectangle of size $\delta \times 2\delta$ contains at most 8 points. Hence, for each point, checking only the next 7 points sorted by $y$ guarantees correctness! Combine step takes $O(n)$, giving $T(n) = 2T(n/2) + O(n) = O(n \log n)$.

Convex Hull: Graham's Scan • $O(n \log n)$

Finds minimal convex polygon enclosing $n$ points. Find pivot $P_0$ (minimum $y$, lowest $x$). Sort remaining points by polar angle with $P_0$. Maintain stack of hull vertices. For each point $P_i$, test orientation using 2D vector cross product. Pop stack while turn is non-left (clockwise or collinear). Push $P_i$. Overall runtime: $O(n \log n)$ dominated by angular sort; linear stack sweep.

Cross-Product Orientation Test (Graham's Scan Invariant):
Given points P_1(x_1, y_1), P_2(x_2, y_2), P_3(x_3, y_3):
Cross Product = (x_2 - x_1)(y_3 - y_1) - (y_2 - y_1)(x_3 - x_1)
• > 0: Counter-Clockwise (Left Turn ⇒ Valid convex hull vertex, keep on stack)
• < 0: Clockwise (Right Turn ⇒ Non-convex interior vertex, pop previous point)
• == 0: Collinear points (Keep only the furthest point from P_0)
Module 2.2

Greedy Strategy & Matroid Optimization: Huffman, Activity Selection & MST

↓

Greedy algorithms construct solutions piece by piece, always selecting the locally optimal choice that appears best at the moment. A greedy algorithm yields a globally optimal solution if and only if the problem exhibits the Greedy-Choice Property and Optimal Substructure.

Huffman Prefix Coding • $O(n \log n)$

Constructs optimal variable-length prefix code. Frequencies inserted into Min-Heap. Repeatedly extract two lowest frequency trees $T_1, T_2$, merge into parent with weight $w_1 + w_2$, and re-insert. Produces prefix-free code tree minimizing average code length $L = \sum f_i \cdot \text{length}_i$.

Activity Selection Problem • $O(n \log n)$

Selects maximal non-overlapping activities. Greedy Choice: Sort all activities by earliest finish time $f_i$. Always pick the compatible activity that finishes first. Proof by induction / exchange argument: Leaving the maximum possible remaining time window never restricts future compatible choices.

MST: Kruskal vs Prim • Cut Property

Cut Property Theorem: For any cut $(S, V \setminus S)$ in connected graph $G$, the lightest crossing edge belongs to every MST. Kruskal's: Sorts $E$ edges, adds edge if endpoints belong to different sets using Disjoint Set Union (DSU with rank + path compression, $O(E \alpha(V))$). Prim's: Expands tree via Min-Heap ($O(E \log V)$).

Fractional Knapsack vs 0/1 Knapsack (Greedy vs DP Contrast):
• Fractional Knapsack: Greedy rule — Sort items descending by value-to-weight ratio p_i / w_i. Take full items while remaining capacity W ≥ w_i, then take fraction W_{rem} / w_{last} of the next item. Optimal in O(n log n).
• 0/1 Knapsack: Fractional greedy FAILS because items cannot be broken. A heavy item with high ratio can leave unfilled slack capacity. Requires Dynamic Programming Bellman table!

Module 2.4

Complexity of Recursion & Call Stack Auxiliary Space

↓

Every recursive call allocates an activation record (stack frame) on the runtime call stack containing return address, parameters, and local variables. The auxiliary space of any recursive algorithm is bounded by the maximum depth of its call stack.

Recursion Tree Depth vs Stack Frames

Space complexity = $\text{Maximum Stack Depth} \times \text{Memory per Stack Frame}$. Merge Sort has recursion depth $\log_2 n$, but requires $O(n)$ heap space for the merge buffer. Naive recursive Fibonacci has recursion depth $n$, consuming $O(n)$ call stack memory while taking $O(2^n)$ runtime.

Tail Call Optimization (TCO)

When a function's final statement is a recursive call, modern compilers overwrite the existing stack frame rather than pushing a new one. Eliminates call stack overflow, transforming $O(n)$ recursion stack into $O(1)$ iterative space.

QuickSort Call Stack Guarantee

By enforcing tail call optimization on the larger partition and making the recursive call on the smaller partition ($\le n/2$), QuickSort is guaranteed never to exceed $O(\log n)$ call stack auxiliary space even in the worst case!
